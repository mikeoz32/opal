# Opal UI Implementation Plan

**Goal:** Provide an optional baseline UI library that makes Opal LiveView
applications useful without copying form, feedback, and data-display markup.

**Architecture:** Stateless Crystal helpers return structural LiveView renders.
Application views retain state. A committed stylesheet generated from complete
Tailwind class literals supplies a zero-runtime-dependency default theme.

## Completed slice

1. Add the explicit `opal/ui` entrypoint and typed `Tone`, `Size`, and
   `ButtonVariant` contracts.
2. Add safe attribute composition and URL-scheme validation.
3. Add buttons, link buttons, badges, alerts, cards, fields, inputs, textarea,
   select, checkbox, radio, switch, and composable tables.
4. Add a precompiled Tailwind theme with inline, linked, and custom-build paths.
5. Add unit coverage, a runnable LiveView showcase, and Chromium interaction
   coverage.
6. Add a native server-controlled modal dialog, optional hook asset, Escape
   and backdrop close requests, DOM-patch preservation, and focus restoration.
7. Add dropdown/menu roving focus, server-controlled tabs, and server-owned
   toast notifications with manual and timed dismissal.
8. Add server-controlled accordions, local accessible tooltips, and
   LiveNavigation-aware pagination.

## Deferred UI work

- drawer with focus trapping and restoration;
- breadcrumb navigation;
- application-owned design tokens and theme generation;
- icon packaging.

Interactive components require explicit keyboard, screen-reader, reconnect,
DOM-morph, and reduced-motion tests. Local presentation behavior should use
LiveView hooks; server state remains application-owned unless a component has a
real independent lifecycle.
